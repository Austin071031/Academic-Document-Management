# 版本4 · 语义对齐检索 — 使用与方法说明

## 这个版本解决什么问题

同一概念在库中以缩写/全称、中文/英文、同义词、上下位词等多种写法出现时，字面
检索必然漏命中。本版本构建**术语规范化层**，做概念级对齐检索。

## 对齐机制

1. **人工对照表** `scripts/aliases.txt`：`概念 = 别名1 | 别名2 | …`（中英/同义/
   上下位，通用科研术语 50+ 条，可扩充）；
2. **自动缩写抽取**：`缩写 (全称)`、`全称（缩写）` 模式从语料双向抽取；
3. 合并为 `concepts.json`（概念 → 词项集合），检索对**查询与索引双向展开**；
4. 输出 `concept_index.json`：每个概念出现在哪些文件/章节/页（跨文件概念地图）。

## 与字面检索的可验证差异

查"缓冲液配方"时：字面 bigram 只命中中文文件；本版本经别名缓冲扩展为
{buffer, buffering solution, 缓冲体系, 缓冲溶液, …}，中文笔记与英文报告同时命中，
且 `matched_terms` 记录对齐路径供复核。

## 克制原则

- 上下位扩展不跨概念跳跃（查"电泳"不自动等于具体技术的实验条件段）；
- 词面对齐只负责"找到候选"，结论强度以 verify.py 逐字校验为准；
- 多义词（MS=质谱/毫秒）靠段落上下文打分排序，低分命中在 answer 中降级说明。

## 依赖与安装

- Python ≥3.9（仅标准库）；无网络依赖。安装＝复制到 `/skills/weekly-skill`。

## 目录约定

```
scripts/aliases.txt    跨语言对照表（资源，可扩充）
scripts/concepts.py    【旗舰】概念映射+概念索引（步骤2.7）
scripts/{inventory,extract,segment,retrieve,verify,report}.py  核心流水线
```

## 词表维护规范

每行 `概念 = 别名1 | 别名2 | …`；`#` 注释；领域案例运行前可按 task.md 补充专业词对，
**补充词表允许，编造文件内容不允许**。扩充建议随案例沉淀回本仓库。

## 运行示例

见 `SKILL.md` 第 4、9 节；合成演示见 `examples/EXAMPLE.md`（标注为示例）。

## 限制与失败处理

- 概念缺别名且无自动缩写时退化为字面匹配并注明；
- 中英混合查询分别走 CJK bigram 与拉丁 token 通道；
- 概念逻辑推理（A 是否蕴含 B）超出词面对齐范围。

## 维护

`aliases.txt` 为唯一需要持续维护的资源；`concepts.py` 的抽取正则集中文件顶部。
